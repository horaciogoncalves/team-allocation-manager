# US-001 — Block Over-Allocation When Creating a New Allocation (UI)

**As a** team lead,  
**I want** the system to prevent me from creating a new allocation that would over-allocate a member,  
**so that** no member is accidentally assigned beyond 100% capacity.

## Acceptance Criteria

1. **Given** a member already has allocations whose overlapping date ranges total 60%,  
   **When** I create a new allocation for that member of 50% that overlaps the same period,  
   **Then** the form prevents submission and displays a clear conflict message.

2. **Given** a member has no existing allocations or the new allocation does not overlap any existing allocation,  
   **When** I submit a new allocation of any valid percentage,  
   **Then** the allocation is created successfully.

3. **Given** the form displays a conflict error,  
   **When** I reduce the new allocation percentage or adjust the date range so the total no longer exceeds 100%,  
   **Then** the error clears and the form can be submitted successfully.

4. **Given** the UI performs client-side validation,  
   **When** the client-side check is bypassed,  
   **Then** the server-side API validation still blocks the request.

## Priority

Must-have
