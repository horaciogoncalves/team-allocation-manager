# US-003 — Treat Allocations Without a Date Range as Indefinite

**As a** system user,  
**I want** allocations with no start or end date to be treated as always active,  
**so that** open-ended commitments are correctly included in conflict detection.

## Acceptance Criteria

1. **Given** a member has an existing allocation of 50% with no date range,  
   **When** I create another allocation for the same member of 60% with any date range,  
   **Then** the system blocks the request because the indefinite allocation overlaps the entire range.

2. **Given** a member has an existing allocation with a defined date range,  
   **When** I create a new allocation with no date range and a percentage that would cause total allocation to exceed 100%,  
   **Then** the system blocks the request.

3. **Given** a member has an existing allocation with no date range,  
   **When** I create a new allocation that does not cause the member to exceed 100%,  
   **Then** the request is allowed.

4. **Given** two allocations both have no date ranges for the same member,  
   **When** their combined percentage exceeds 100%,  
   **Then** the second allocation is blocked (or the conflicting update is blocked).

## Priority

Must-have
