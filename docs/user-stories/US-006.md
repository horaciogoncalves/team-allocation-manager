# US-006 — Enforce Over-Allocation Validation on `PUT /api/allocations`

**As a** developer,  
**I want** the update-allocation API to enforce conflict rules,  
**so that** existing allocations cannot be edited into an invalid state.

## Acceptance Criteria

1. **Given** a valid `PUT /api/allocations` payload that does not cause over-allocation,  
   **When** the request is processed,  
   **Then** the allocation is updated and a `200 OK` response is returned.

2. **Given** a `PUT /api/allocations` payload that would cause over-allocation,  
   **When** the request is processed,  
   **Then** the allocation is not updated and a `409 Conflict` (or `400 Bad Request`) response is returned with conflict details.

3. **Given** an allocation is being updated,  
   **When** the conflict check runs,  
   **Then** the system excludes the allocation being updated from the existing overlap calculation.

4. **Given** the payload changes an allocation to have no date range,  
   **When** the member already has allocations whose total with the new indefinite allocation exceeds 100%,  
   **Then** the update is blocked.

## Priority

Must-have
