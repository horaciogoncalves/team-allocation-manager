# US-005 — Enforce Over-Allocation Validation on `POST /api/allocations`

**As a** developer,  
**I want** the create-allocation API to enforce the same conflict rules as the UI,  
**so that** the data layer remains consistent regardless of client.

## Acceptance Criteria

1. **Given** a valid `POST /api/allocations` payload that does not cause over-allocation,  
   **When** the request is processed,  
   **Then** the allocation is created and a `201 Created` response is returned.

2. **Given** a `POST /api/allocations` payload that would cause over-allocation,  
   **When** the request is processed,  
   **Then** the allocation is not created and a `409 Conflict` (or `400 Bad Request`) response is returned with a structured error object.

3. **Given** a `POST /api/allocations` payload with `start_date` or `end_date` omitted,  
   **When** the request is processed,  
   **Then** the indefinite-allocation rule is applied during validation.

4. **Given** an invalid payload (e.g., percentage > 100 or < 0),  
   **When** the request is processed,  
   **Then** the request is rejected before conflict detection runs.

## Priority

Must-have
