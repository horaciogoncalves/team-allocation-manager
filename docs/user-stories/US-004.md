# US-004 — Provide Clear, Actionable Conflict Error Messages

**As a** team lead,  
**I want** to see exactly which existing allocations conflict and how much capacity is already used,  
**so that** I can quickly resolve the issue.

## Acceptance Criteria

1. **Given** a conflict is detected,  
   **When** the error is returned,  
   **Then** the message includes the member’s name and the total overlapping percentage that would result.

2. **Given** a conflict is detected,  
   **When** the error is returned,  
   **Then** the message lists the conflicting allocation(s) with project name, percentage, and date range (or “Indefinite” if no dates).

3. **Given** the request is made via the API,  
   **When** validation fails,  
   **Then** the response returns a machine-readable error code (e.g., `OVERALLOCATION_CONFLICT`) along with the human-readable message and conflict details.

4. **Given** the request is made via the UI,  
   **When** validation fails,  
   **Then** the error is displayed near the relevant fields and in a summary alert.

## Priority

Must-have

## Notes / Open Questions

- Should the message include suggested maximum allowable percentage? *(Recommended.)*
