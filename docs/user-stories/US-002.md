# US-002 — Block Over-Allocation When Updating an Existing Allocation (UI)

**As a** team lead,  
**I want** the system to prevent me from updating an allocation in a way that would cause the member to be over-allocated,  
**so that** edits do not accidentally introduce conflicts.

## Acceptance Criteria

1. **Given** a member has two allocations of 50% each for an overlapping period,  
   **When** I edit one allocation to 60%,  
   **Then** the form blocks the update and explains that the member would be 110% allocated during the overlap.

2. **Given** I am updating an allocation,  
   **When** I change only non-conflicting fields (e.g., project, notes) and the member’s capacity remains ≤100%,  
   **Then** the update succeeds.

3. **Given** the updated allocation itself originally contributed to the total,  
   **When** the conflict check runs,  
   **Then** the system excludes the current allocation record from the existing total before recalculating.

4. **Given** the UI form shows a conflict,  
   **When** I adjust the percentage or dates so the total no longer exceeds 100%,  
   **Then** the error clears and the update is permitted.

## Priority

Must-have
